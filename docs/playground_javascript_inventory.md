### Shipped code

Each has a matching source map. The build inserts a SHA-256 stamp in the bundled compiler build worker. Its unit messages return that stamp before the page can reuse generated objects. To replace that machinery, verify cache hits with the same host and cache refusal after changing the object-producing host. The service worker carries isolation headers and the HTML module script loads the app. The ZIP/download Blob URLs carry data. There is no project extension activation script or TypeScript entry. Preserve the two grammar fixture suites when changing those JSON files. The playground editor has a different runtime. ### Probes and checks

The production editable compiler Build checks a candidate before selecting it. Its parser, visibility, completion, hover, emitter, interpreter, package and target probes appear in the `compiler-build.mjs` row. Keep a host-side comparison against independent expected values when the candidate itself is editable. Moving all expectations into mutable candidate code would let a broken candidate certify itself. The warm LLVM path separately compiles and runs a known program. Grammar install and transport validation run on individual requests.

Four scripts send JavaScript for execution inside the browser. `diagnose-worker-retirement` probes worker lifecycle and trace events. `test-shared-compiler` drives child creation, injected failures, cancellation, retirement and replacement through page evaluation. `profile-execution` installs its performance observer before navigation. `verify-deployment` injects saved state and browser hints, reads rendered geometry and retrieves actual download bytes. Keep these observations at the host until an equivalent caller can observe the same browser state. Companion Tower fixtures can own the guest inputs and expected semantics. The [test inventory](test-inventory.md) covers the separate test modules, editor assertions and runner registrations. The module inventory also includes scripts invoked outside the test directories.

### Example projects

Previously, `build.mjs` copied three sources individually and nine in a loop. `projects.mjs` held their ordered names. At startup `app.mjs` joined two lists by index, assigned names and stable IDs, and assembled single-file projects. The ordinary build now supplies the example source directory to `package_playground_assets`. Tower writes the standalone sources and an ordered `examples.json` containing IDs, display names and ordered file records with source text. The extra asset lets the browser hydrate all examples with one fetch. Individual source URLs remain available to existing callers. Invalid UTF-8 and embedded NUL in a registered source fail the build with the file path.

The app loads the catalog and builtin manifest, installs missing projects, and retains the bundled text for Restore. Existing IDs preserve saved edits. A future Tests entry can use the same catalog schema with multiple files. The draft in the host 7 receipt awaits published test-mode grammar, test discovery and source-mapped failure reporting. Its four files are separate from the shipped catalog.
