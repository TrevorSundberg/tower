## Layout result ownership

1. The coordinator's `sem_layout_request` checks the subject's world against the program root, registers the result kind there and attaches the component to the subject. It registers the component pointer for teardown before reserving offsets or exposing the graph request. If the append itself fails there are no offsets yet. Subsequent setup failures leave cleanup able to find each allocated offsets vector. The component lives on the entity. The context owns the registry buffer and the obligation to release offsets.
2. `sem_layout_discover` reserves a write on the Compiler/Layout interval `[id, id+1)` and reads on `[dependency, dependency+1)` for aggregate inputs. The reserved ranges are logical query IDs. The actual worker reads the frozen type, ordered fields and completed dependent sizes/alignments. It writes its result's size, alignment, error fields and preallocated `offsets[0..length)`. Unique field ownership is needed for the coordinator's later byte-offset writes.
3. `sem_layout_execute` opens the entity view after allocation, takes ready layout tickets and borrows extra lanes under the shared budget. The pool receives the embedded kernel. Its pinned view protects lifetime. The ticket and dependency graph authorize the reads and publication. Small layouts run on the caller.
4. After a job returns, the coordinator copies size, alignment and offsets to the authoritative Foundation nodes before `work_finish` releases its dependents. Independent jobs can remain in flight. On a layout error the pump drains admitted work and selects the lowest failed task ordinal before reporting it. The pump closes the view and releases the lane receipt on exit.
5. `work_cancel` invalidates graph tickets and ready work. Physical retirement belongs to the pool. `sem_layout_dispose` calls `work_pool_close`, which receives all outstanding jobs, stops and joins threads, and releases transport storage. It then disposes each registered offsets vector and the registry. Context, program and world teardown follow their existing order. The synchronous pump has no asynchronous mid-kernel cancellation API. No alias, mutation permission or lifetime guarantee is inferred from a typed pointer.
