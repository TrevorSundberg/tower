Implement only a completed-prefix selection cursor, not an active-work scheduler: add `SemanticLowerSelection { signature_next: usize; expression_next: usize; revision: u64; profile: u64; }` and `SemanticContext.lower_selection` in `semantic_context_types.tower`. No heap array, task ownership, captured payload or readiness copy is added; measure actual `sizeof`/snapshot-stack growth instead of claiming zero memory cost.
In `semantic_lowering_work.tower`, add coordinator-only `sem_lower_selection_advance(c, signature)`: from that phase's cursor, use the current function subject/query identity and skip only absent queries or `WorkState.Succeeded`; stop at every other state, including Failed. The invariant is that every skipped position is absent or terminal-success for this graph identity, not that every preceding function was once dispatched.
Keep the entire `sem_lower_register` scan and its Body/KnownSnapshot/own AggregatePrepare dependencies. After a newly attached result is fully sealed/demanded successfully, set its phase cursor to `min(cursor, i)`; this admits a body/signature discovered later at an old ordinal, as well as an appended function. Missing-body/signature skips therefore cannot become a permanent negative cache. Admission failure follows existing cancellation/cleanup; no cursor may authorize work.
At `sem_lower_frontier` entry, synchronize the cursor's revision/profile with `c.queries`, clearing both positions on mismatch; then run the existing registration calls. Advance the selected phase(s), start the function scan at their minimum, and skip a phase only below its own cursor. Preserve the existing function-then-Signature/Expression order and `SemanticPreparationWindow` bound. Do not mutate cursor state from worker snapshots.
Advance again only at the next pump's joined entry, after the preceding successful stage publication/`work_finish`; no change to ticket completion or lease release. Each newly completed prefix position is then inspected once instead of on every later window. A blocked early position intentionally keeps the suffix scan: this small cursor does not solve interspersed unfinished work or registration's155990 visits.
Waiting→Ready (`work_finish` consumer wakeup), Running→Waiting (`work_suspend_access`) and Running→Ready (`work_yield`) never cross the cursor because non-Succeeded entries are not skipped; each retry still calls `work_take_task`. Succeeded cannot become eligible again in the same graph identity. `work_reset` clears rows and changes identity; it is not supported semantic payload reuse, so cursor reset must not imply incremental recompilation support.
Invalidate both cursors at the existing function-compaction sites `sem_body_prune` in `semantic_body_work.tower` and `sem_link_functions` in `semantic_modules.tower`; both currently precede lifecycle lowering via `sem_run`, but explicit invalidation prevents relying on ordinal stability across compaction. `sem_context_init` already zeroes the whole descriptor; clear the value in `sem_lower_dispose` after its existing joined-worker check. Appends use registration rewind; no function reordering hook or new edit API is introduced.
Leave `sem_lower_state`/`sem_lower_finish` full source-order scans intact: an earlier Waiting producer still delays a later error, signature errors precede expression errors, and cycles remain owning-pipeline quiescence decisions. Preserve block refresh after aggregate publication, completion reservation, stale dispatch rejection, cancellation and all stage holds/publish/discard/worker drain behavior.
