- Root cause: installed Clang19.1.1 expands driver `--target=x86_64-pc-windows-msvc` into frontend `-triple x86_64-pc-windows-msvc19.33.0`. The published IR declares the unversioned triple. Its actual Windows x64 ABI/layout is consistent; this is version decoration, not Linux runtime code being linked into Windows.
- [LLVM19 CodeGenAction](https://github.com/llvm/llvm-project/blob/llvmorg-19.1.1/clang/lib/CodeGen/CodeGenAction.cpp#L1080) compares the two triple strings before reporting the warning and replacing the module triple. Retained `driver.stderr` captures the exact original frontend argv.
- Fix: keep Clang's existing `-O2 -c` path and pass the same declared target explicitly with `--target="$target" -Xclang -triple -Xclang "$target"`. The [documented forwarding option](https://clang.llvm.org/docs/ClangCommandLineReference.html#cmdoption-clang-Xclang) and installed `clang -cc1 -help` support this boundary; `explicit_triple.stderr` records its argv. No warning flag, ABI substitution or resource rewrite.
