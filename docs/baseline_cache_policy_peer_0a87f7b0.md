Implementation scope: opt in only where the caller proves one bound environment/world, unchanged immutable seed and coordinator ownership throughout installation. `driver_request_prepare` creates that fresh world/environment and does not clear the world before `driver_request_close`; this is the smallest proven CLI scope. If the policy is made general, explicitly establish the same seed guarantee or retain full invalidation—do not silently broaden the public install/reset contract.
Keep `ModuleEnvironment.cache`'s existing16-snapshot bound. `module_cached` checks lexical root path **and current root bytes**; `module_cache_valid` re-resolves every dependency edge against current aliases/search roots/input overrides and compares path plus text. Retaining an entry is not accepting it; leave these checks on every hit, including a changed transitive resource or newly nearer file.
Concrete unsafe shortcut: cache `language.tower` importing `rules.tower` with `parse Statement='old';`, then change only rules to `'new'`. Unchanged language/Foundation top-level bytes are insufficient; skipping dependency validation would accept stale `old`. Existing changed-source/new-relative-file controls exercise this distinction. `syntax_world_matches` itself checks only the installed file's bytes, not dependency freshness.
`frontend_modules_clear` removes source overrides, not cache/session ownership; do not remove or repurpose it. Configure/fallback/builtin changes must still affect subsequent resolution. Original and canonical CLI environments (`request.modules` versus `request.generated`) remain distinct: canonical staging selects bundled resources instead of custom language overrides even though both bind the same world.
Grammar activation remains ordered: imports finish dependencies before importer publication; `module_grammar_visit` deduplicates modules and applies dependency declarations before local ones; `=` replacement/`|=` extension and token order remain unchanged. `syntax_next` releases recognition/lookahead before publishing a new revision. Cached imports must not activate rules before the source import boundary or leak a caller's local override into a sibling.
Snapshots contain parsed syntax, not target-specific semantic results: `module_cache_store` runs before checking; `module_clone` retains immutable grammar declarations but freshly clones ordinary roots/import syntax, rebuilds import captures and deduplicates modules by lexical path within each request. `compiler_clone_tree_result` copies syntax provenance/matches, not Foundation state. Nominal types are bound to the new request's declarations; identical layouts/spellings in distinct modules do not become one type.
Target32/64 and execution profiles still initialize/check a fresh SemanticProgram (`execution_session_compile_sources_world` / `frontend_unit_compile`). Module cache has no width/profile key because it caches syntax only. Keep that boundary; do not reuse checked layout, capture, executable or lowering components. Existing SyntaxVersion/ParserStructure caches retain their world/budget/seed, ordered grammar, mode and specialization checks; this candidate adds no revision equivalence.
Retained graphs own source snapshots, ordinary roots, import trees and grammar references; the environment anchor pins its world. Keep all refs until eviction/disposal; do not transfer a snapshot's roots directly into a request. Cache snapshots are untracked private graphs; active request counts, diagnostic sources and used-file lists retain current publication/reset behavior.
Keep idle-session retirement and generation increment in this first candidate. Active leases retain cursor/pins and drain normally; an old-generation lease must not re-enter the idle cache. Full reset/disposal still clears all snapshots; `frontend_modules_try_destroy` rejects live requests, and driver close destroys both environments before clearing/disposing the world.
Failure remains fatal with its original cause/offset: baseline failure publishes no new baseline; clone/cache-store failure preserves prior entries and frees partial owners. Snapshot storage reserves its replacement slot before eviction. Retention can shift a real Capacity boundary, so do not weaken caps, map Capacity to Memory, or turn a failed required clone into a cache miss/success. Completed dependency snapshots from a failed outer parse are not permission to cache that incomplete/cyclic outer graph.
