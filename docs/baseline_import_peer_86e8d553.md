`syntax_session_open_result` allocates a fresh installation session, pins the world's current immutable seed and creates a fresh owned module graph on its first import. `module_load` uses that graph's initially null `import_session`, never `environment.compilation_session`; recursive imports retain separate active readers and completed siblings reuse only this graph's reader. Existing active graphs are not imported into the new graph.
Thus an old idle/active lease can coexist with an empty cache without donating its old seed to installation. All retained entries were created or cloned from entries created within this call. Coordinator ownership excludes concurrent reset/source mutation; `syntax_world_publish` rejects a pinned world, validates declaration/document ownership and prepares fallible source storage before replacing the baseline. No worker completion is forced here.
After publication, idle retirement destroys the obsolete parser; active leases keep their input/revision pins. `module_session_release` rejects old-generation return to the idle slot and destroys it only when its graph drains. The installation's deferred `syntax_destroy` releases its graph/import reader/source/document/pins independently of retained snapshot owners. An environment anchor prevents world disposal; try-destroy rejects live request graphs.
No blanket statement that failure purges is justified: **unchanged failure paths return before either reset**. Prior baseline/generation survive; already completed dependency snapshots can remain, while the failed installation's private owners are destroyed. The new negative explicitly checks this preservation. A subsequent successful install with that nonempty cache takes full purge. No failed parse/publication is relabeled successful or newly cached as a complete outer module.
`frontend_world_clear` retires seed/baseline/structure caches only after joins and rejects pins/busy workers. A surviving nonempty module cache makes the new guard false. Same-world identity alone is not the seed proof; only the empty-cache/fresh-reader case is exempt. Null environment retains no persistent import cache and retirement is a no-op.
`syntax_world_matches` remains a **top-level-byte** fast path before the guard; it neither advances generation nor validates transitive imports. Do not claim it refreshes a changed dependency's installed baseline. Ordinary later `module_cached` calls still compare lexical root path/text and re-resolve every dependency edge's current path/text, including source overrides, builtin aliases, nearer relative files and fallback changes.
Snapshots remain parsed syntax: `module_cache_store` runs during successful import parsing before semantic attachment, rejects incomplete/cyclic graphs, and privately clones dependencies/ordinary roots/import syntax before publication. Grammar declarations are retained immutable owners. `compiler_clone_tree_result` preserves syntax/provenance, not request semantic components; each request checks its own declarations, nominal types, target layout, captures and executable state.
`ModuleCacheEntries` remains16; publication reserves its slot before retiring the oldest snapshot. First clone/resource failure remains sticky, partial clones are destroyed, old entries survive denial and retry creates a fresh graph. The new fixture reuses the existing named128MiB budget without changing it; denial tests still derive occupied bytes from the actual snapshot, and loops derive cache/graph bounds. No padding/cap increase or error-enum normalization was added.
Driver code is unchanged: `driver_install_grammar` installs Bedrock then Foundation; original `request.modules` honors custom paths, while canonical `request.generated` is a separate environment configured from bundled resources. Both bind the same request-owned world but never share module-cache entries. Close destroys both environments before clearing/disposing the world.

The new oracle is independent of a measured result: literal source changes must parse; old/new declaration identities differ while an old request still pins the old declaration. Exact reused identity on the first request confirms cache use, not merely successful reparsing. The world-clear test intentionally starts with pre-existing snapshots and requires an empty cache after install; successful replacement also requires generation change.
Unchanged tests cover transitive relative resolution/alias/fallback changes, dependency-first diamond order, local overrides and explicit-language negatives; semantic-isolation adds a marker component only to a request root and requires fresh/cached roots remain unmodified. Existing lease tests assert old sessions never re-enter the idle slot after reset, current sessions do, and busy environment destruction fails.
Existing startup/clone controls preserve exact Capacity and Invalid expectations, repeated failure, prior snapshots/entity counts and final grants; they are not replaced by the new positive fixture.
