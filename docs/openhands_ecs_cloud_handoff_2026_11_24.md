## What is implemented

The compiler represents grammar declarations, parse nodes, ASTs, types, Foundation operations, transforms and compiler work as world-owned entities/components. Ordered and named relations carry hierarchy. Derived LR tables, queues, indexes and execution caches accelerate those operations. Stable sparse payloads and dense table columns serve different access patterns. A dense column of pointers still entails a payload lookup. There is no general alias or vectorization guarantee from archetype membership. [Compiler services](compiler-services.md) · [Storage and implementation audit](compiler_ecs_reconciliation_4e7ef17b.md)

`CompilerWork`, `WorkGraph`, `WorkPool` and `compiler_kernel_dispatch` support ready work across files and independent work inside a file. Workers use private scratch and stages. The coordinator freezes inputs and reserves accesses before dispatch, drains workers on cancellation, and publishes structural changes and retained references after joining. Ordered effects, shared interning, coordinator publication and a shared LLVM context impose real ordering constraints. Inspect ordinary-process overlap and elapsed time before widening another phase. [Within-unit and backend attribution](compiler_within_unit_e0e3530b.md) · [Threading handoff](compiler_ecs_threading_handoff.md)

Type, `decltype`, layout, body, lowering and known-value demands use the dependency graph. The ordinary interpreter evaluates reached compile-time work. Resumable state must preserve lexical progress, effect order, alias identity, frame ownership and revisions. Tests cover reordered inputs, actual demand cycles, stale results, and a retained-world import diamond whose shared leaf changes, fails and is repaired. A fresh cloud checkout can run these fixtures without the prior chat. [Dependency permutations](dependency_permutations_4e7ef17b.md) · [Independent oracle](dependency_permutations_peer_de664a95.md) · [Retained import diamond](retained_import_diamond_587d2b36.md)

Git shows exactly two Tower replacements between that freeze and c49, both `lr_work.tower` (compiler and fixture). ## Research and language direction

Stronghold is intended to provide type/memory safety, definite initialization, checked handles and provable access for fast ECS and vectorized work. Tower and Foundation retain their lower-level contracts. Keep ownership, access and provenance expressible on the same entities. Consult Flecs for staged structural changes, archetype query behavior and dense versus sparse storage. A stable pointer protects an address; it does not authorize concurrent mutation. Require an actual disjointness proof before emitting alias promises. [Flecs systems](https://www.flecs.dev/flecs/Systems.html) · [Flecs component traits](https://www.flecs.dev/flecs/ComponentTraits.html) · [Burst aliasing](https://docs.unity3d.com/Packages/com.unity.burst@1.8/manual/aliasing.html)

The proposed grammar specialization is a distinct future experiment. `comptime` requests a known value through ordinary evaluation. Specialization produces residual code from known bindings, potentially fields of a struct or a whole immutable grammar. Compilation selects a target; snapshotting serializes resumable state; scheduling chooses when to compute; inlining, unrolling and code-size budgets are optimization policy. A typed library/API experiment can precede syntax. Preserve effects, identity, mutable inputs, invalidation and target profile. Compare startup, throughput, compilation cost, code size and instruction-cache behavior before shipping grammar-specific code. The Emscripten/Binaryen constructor evaluator, Wizer and weval illuminate different parts of the design. The historical journal records the distinctions and the proposed interpreted fallback after a grammar edit.
